## Pattern

When a project generates a **static HTML dashboard** (e.g. `docs/test-dashboard/index.html` published to GitHub Pages), also provide a **live Blazor equivalent** at a `/dashboard` route inside the running app. Both views read from the **same `summary.json` data source** — no duplication, always in sync.

## Data Source Access from Blazor Server

The static dashboard JSON (`docs/test-dashboard/summary.json`) lives at repo root, outside the web project. Read it from Blazor Server via filesystem:

```csharp
@inject IWebHostEnvironment Env

var contentRoot = Env.ContentRootPath;  // e.g. C:\repo\src\MyWeb\
var repoRoot = Path.GetFullPath(Path.Combine(contentRoot, "..", ".."));
var jsonPath = Path.Combine(repoRoot, "docs", "test-dashboard", "summary.json");

if (!File.Exists(jsonPath))
{
    _error = $"summary.json not found at: {jsonPath}";
    return;
}

var json = File.ReadAllText(jsonPath);
_summary = JsonSerializer.Deserialize<DashboardSummary>(json, new JsonSerializerOptions
{
    PropertyNameCaseInsensitive = true
});
```

**Why it works:** In local dev and Aspire-launched mode, `ContentRootPath` = the web project folder. `../..` navigates to repo root reliably. This path is deterministic and works without any configuration.

## Component Structure

```
TestDashboard.razor
├── Loading skeleton (MudSkeleton × N)
├── Error alert with actionable guidance
└── Data view
    ├── Aggregate totals strip (Total / Passed / Failed / Skipped)
    └── Per-suite cards
        ├── Header: label + status chip
        ├── Description text
        ├── Stat row (Total / Passed / Failed / Skipped)
        ├── Pass-rate progress bar
        ├── Latest run date + history sparkline
        └── [optional] Failing test alerts
```

## data-testid Coverage

Always add these attributes for E2E test stability:

| Element | testid |
|---|---|
| Root container | `data-testid="test-dashboard"` |
| Totals strip | `data-testid="dashboard-totals"` |
| Suites grid | `data-testid="dashboard-suites"` |
| Per-suite card | `data-testid="suite-card-{suite.Id}"` |
| Status chip | `data-testid="suite-status-{suite.Id}"` |
| Progress bar | `data-testid="suite-progress-{suite.Id}"` |
| Error state | `data-testid="dashboard-error"` |
| Generated-at | `data-testid="dashboard-generated-at"` |

## Refresh Cycle

The data is **file-based and read on page load** (no polling needed — tests don't run continuously). Refresh = navigate away + back, or F5. If real-time updates are needed later, a `PeriodicTimer` + `StateHasChanged()` loop can be added (see `Home.razor` for the pattern).
